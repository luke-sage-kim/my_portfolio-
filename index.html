문제
지식 문서 업로드 중 OOM이 발생해 챗봇 서비스 전체가 응답하지 않음. 즉시 재기동으로 복구한 뒤 근본 원인 분석에 착수.
원인
리인덱싱 시 전체 청크를 OpenSearch에 한 번의 요청으로 적재하면서 Heap 메모리가 급증하는 구조.
조치
  • 최대 200건 단위 분할(Bulk) 적재로 바꿔 메모리 사용량에 상한을 둠
  • 임베딩 실패 시 문서가 "업로드 중"으로 고착되던 문제에 실패 상태 처리 로직을 추가해 사용자가 재시도할 수 있게 함
180MB 이상에서 실패하던 업로드를 300MB 이상까지 정상 처리 · 이후 동일 장애 재발 0건

FCM 인증 방식 변경으로 발생한 글로벌 로그인 장애 2시간 내 복구

문제
Google FCM Legacy API 지원 종료로 로그인 과정의 푸시 토큰 등록이 실패해 전 세계 유저가 로그인하지 못하는 장애 발생.
제약
기존 서버가 Java 8 환경이라 신규 인증 방식(HTTP v1, OAuth2)을 바로 적용할 수 없음. 전체 버전 마이그레이션은 3일 이상 소요.
판단·조치
인증 기능만 별도 서버로 분리 구현해 기존 서버의 변경 범위를 최소화. "지금 서비스를 살리면서도 이후 정상 구조로 되돌릴 수 있는 해법"을 기준으로 선택.

DB 서버 다운 원인 분석과 서버 성능·데이터 정합성 개선

문제
DB 서버 다운과 높은 부하, 로그 인덱스 필드가 끝없이 늘어나는 문제가 함께 발생.
원인
고빈도 API에서 save가 반복 실행되는 구조, 유저 ID가 로그 필드명으로 저장되는 구조(mapping explosion).
조치
  • 반복 save를 일괄 저장으로 변경, 나뉘어 있던 로그인 요청을 하나의 API로 통합
  • 게임 데이터 Enum 구조를 Map 기반 조회 구조로 변경
  • 로그 구조를 ID를 값으로 저장하도록 변경
  • 점수 int 오버플로를 long 필드 추가와 무중단 데이터 마이그레이션으로 해결
DB 쓰기 30% 감소 · 로그인 호출 8회 → 1회 · 서버 메모리 30% 감소 · Kibana 필드 3,000개 → 700개
